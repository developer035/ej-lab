Part 1: Derived Query Methods
Suppose we want to find students by name.
Normally, we might write SQL: SELECT * FROM students WHERE name = 'Rahul';
With Spring Data JPA, we can simply write: List<Student> findByName(String name);
Spring understands the method name and automatically generates the appropriate query. 
For example: 
findByName(...)
findByEmail(...)
findById(...)
We can also build more complex queries: 
findByNameContaining(...)
findByNameStartingWith(...)
findByEmailContaining(...)
findByNameIgnoreCase(...)
This is why they are called derived query methods.
The query is derived from the method name. 
Step 1: Open StudentRepository.java
Currently you have: 
package com.example.ucs067.studentmanagement.repository;
import com.example.ucs067.studentmanagement.Student;
import org.springframework.data.jpa.repository.JpaRepository;

}
We are going to add our first derived query method: 
List<Student> findByName(String name);
But before doing that, we need the List import.
So change it to:
package com.example.ucs067.studentmanagement.repository;
import com.example.ucs067.studentmanagement.Student;
import org.springframework.data.jpa.repository.JpaRepository;
import java.util.List;
public interface StudentRepository extends JpaRepository<Student, Integer> {
    List<Student> findByName(String name);
}
What this means: List<Student> findByName(String name);
means:
"Find all Student records where the name field matches the given name."
Notice something important:
We are not writing SQL.
Spring Data JPA interprets: findByName
and creates the database query for us. 
With Experiment 4, we learned:
JpaRepository gives us ready-made CRUD operations.
For example:
studentRepository.findAll();
studentRepository.findById(id);
studentRepository.save(student);
studentRepository.deleteById(id);
But what if we want:
"Give me all students whose name is Rahul."
We could write SQL:
SELECT * FROM students WHERE name = 'Rahul';
But Spring Data JPA allows us to simply write: 
List<Student> findByName(String name);
Spring looks at the method name and automatically creates the query.
This is called a Derived Query Method.
Add more derived query methods
Your current interface is correct. Let's add two more methods.
Change it to:
Copy and Paste:
package com.example.ucs067.studentmanagement.repository;
import com.example.ucs067.studentmanagement.Student;
import org.springframework.data.jpa.repository.JpaRepository;
import java.util.List;
public interface StudentRepository
        extends JpaRepository<Student, Integer> {
    List<Student> findByName(String name);
    List<Student> findByNameContaining(String keyword);
    List<Student> findByEmail(String email);
}
The 3 yellow warnings are not errors; IntelliJ is essentially telling you these methods are currently unused. 
Method
Meaning
findByName(String name)
Find students whose name exactly matches
findByNameContaining(String keyword)
Find students whose name contains the keyword
findByEmail(String email)
Find student(s) with a particular email
JPA Derived Query
Conceptually Equivalent To 
findByName("Rahul")
SELECT * FROM students
WHERE name = 'Rahul';
findByNameContaining("Rah")
SELECT * FROM students
WHERE name LIKE '%Rah%';
Spring Data JPA understands keywords such as:
findBy
And
Or
Containing
StartingWith
EndingWith
GreaterThan
LessThan
Between
OrderBy
So the method name becomes a query definition. 
Step 2: Create an endpoint using findByName()
Now let's connect the repository method to our REST API.
Open HelloController.java.
Add this method inside the HelloController class:
@GetMapping("/students/search/name/{name}")
public List<Student> searchByName(@PathVariable String name) {
    return studentRepository.findByName(name);
}
So conceptually: 
Browser / Client
      ↓
GET /students/search/name/Rahul
      ↓
HelloController
      ↓
studentRepository.findByName("Rahul")
      ↓
Spring Data JPA
      ↓
MySQL
      ↓
Student records
We did not write any SQL query.
We only declared findByName(), and Spring Data JPA generated the database query automatically. 
For example: GET Request
http://localhost:8081/students/search/name/Rahul
should return: 
[
  {
    "id": 1,
    "name": "Rahul",
    "email": "rahul@example.com"
  }
]
Copy and Paste. Add and Try these methods also:

Part 2: Pagination
Now we move to the second major part of Experiment 5:
Adding pagination and sorting to a listing endpoint.
Why pagination?
Suppose your database contains: 
10 students
1,000 students
100,000 students
1,000,000 students
If /students returns every record at once, it can become inefficient.
Instead, we can request:
Page 0 → students 1–5
Page 1 → students 6–10
Page 2 → students 11–15
Spring Data JPA makes this very easy because JpaRepository already supports pagination. 
Step 1: Change the controller
In HelloController.java, find your current method:
First, add these import at the top of HelloController.java:
import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;
Then add:
@GetMapping("/students/page")
public Page<Student> getStudentsPage(Pageable pageable) {
    return studentRepository.findAll(pageable);
}
Run this request:
http://localhost:8081/students/page?page=0&size=2

Part 3: Sorting
Now let's add sorting so students can be retrieved, for example: 
Request:
/students/sort/name
Response:
Amit
Neha
Priya
Rahul
Ravi
Step 1: Add the Sort import. Open HelloController.java. Add:
import org.springframework.data.domain.Sort;
Step 2: Add the sorting endpoint. Now, just below the pagination method, add:
// GET students sorted by name
@GetMapping("/students/sort/name")
public List<Student> getStudentsSortedByName() {
    return studentRepository.findAll(Sort.by("name"));
}
Step 3: Test sorting. Make sure the application is running in IntelliJ. Now open this URL in Chrome:
